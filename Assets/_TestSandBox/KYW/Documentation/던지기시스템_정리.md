## 던지기 시스템 정리 (KYW)

### 범위
- 플레이어가 들림(Held) / 던져짐(Thrown) 상태일 때 입력 차단과 물리(중력/속도/충돌/부모관계) 전환 흐름
- 관련 스크립트: `SpelunkyPlayerController`, `PlayerStunInvincibleDie`, `PlayerObjectPickup`, `PlayerObjectThrower`, `PlayerMovement`, `PlayerJump`, `PlayerClimbing`, `PlayerInteraction`

### 핵심 상태와 타이머
- `PlayerStunInvincibleDie`
  - [Networked] `IsHeld`, `IsThrown`, `IsStunned`, `IsInvincible`, `IsDead`
  - `SetHeld(bool)`: 권한/사망/무적 체크 후 설정
  - `SetThrown(float)`: 권한/사망/무적 체크 후 `IsThrown = true` + `ThrownTimer` 시작
  - `FixedUpdateNetwork()`: `ThrownTimer` 만료 시 `IsThrown = false`

### 들림(Held) 절차
1) 입력: 플레이어가 `PlayerObjectPickup`으로 대상 선택 → `PickupObjectRpc(objectId)`
2) 서버: `PickupObject()`
   - 캐릭터: `IPlayerInteraction.OnPickedUp()` → 내부에서 `PlayerStunInvincibleDie.SetHeld(true)`
   - 아이템: `IItemInteraction.OnPickedUp()`
3) 공통 마무리(`FinalizePickup`):
   - 부모/위치: 들고 있는 손(`Hand`) 하위로 `SetParent(Hand)`, 캐릭터는 `localPosition = playerHoldOffset`, `localRotation = identity`
   - 물리 비활성화: `DisableItemPhysics()`
     - `Rigidbody2D.bodyType = Kinematic`, `linearVelocity = 0`, `angularVelocity = 0`, `gravityScale = 0`
     - `Collider2D.isTrigger = true`

### 던지기(Thrown) 절차
1) 입력: `PlayerObjectThrower.ProcessInput()`에서 `ThrowItem` 버튼 상승엣지 감지 → `ThrowObjectRpc(mouseWorldPos)`
2) 서버: `ThrowObject()` → `ReleaseObject(obj, applyForce: true, direction)`
3) `ReleaseObject()` 공통 처리:
   - 캐릭터: `IPlayerInteraction.OnReleased()` → `SetHeld(false)`
   - 상태 플래그: 캐릭터는 `PlayerStunInvincibleDie.SetThrown(1.5f)` (타이머 만료 시 자동 해제)
   - 부모/회전:
     - 캐릭터: 즉시 `SetParent(null)`, `rotation = identity`
     - 아이템: 부모 해제 지연(`TickTimer` 약 0.05s 후 `SetParent(null)`)
   - 물리 복구:
     - 던지기: `EnableItemPhysics(obj, dir)` → `Rigidbody2D.bodyType = Dynamic`, `gravityScale = 1`, 속도 0 초기화 후 `AddForce(dir * throwForce, Impulse)`, `Collider2D.isTrigger = false`
     - 일반 해제: `EnableItemPhysicsWithoutForce(obj)`로 Dynamic/중력만 복구

### 물리 전환 요약
- Held
  - Parent: `Hand` 하위
  - Rigidbody2D: `Kinematic`, `gravityScale = 0`, `velocity = 0`, `angularVelocity = 0`
  - Collider2D: `isTrigger = true`
  - Flag: `IsHeld = true`
- Thrown
  - Parent: 캐릭터 즉시 분리(아이템은 0.05s 지연 후 분리)
  - Rigidbody2D: `Dynamic`, `gravityScale = 1`, 속도 초기화 후 `AddForce`
  - Collider2D: `isTrigger = false`
  - Flag: `IsThrown = true` (타이머 만료 시 false)

### 입력 차단(현재)
- 중앙: `SpelunkyPlayerController.BeforeUpdate()`에서 `IsDead || IsStunned || IsHeld || IsThrown`이면 입력 변수를 초기화하고 반환
- 개별 모듈: `PlayerMovement/Jump/Climbing/Interaction.ProcessInput()` 시작부에서도 동일 조건으로 조기 반환(중복 게이팅)

### 동작 특성
- Thrown 동안 `PlayerJump`의 커스텀 중력 적용은 중단되며, `Rigidbody2D.gravityScale = 1`로 유니티 내장 중력만 작동
- Held 동안 `Kinematic + gravityScale = 0`으로 모든 외력/중력 차단
- `IsThrown` 해제는 `PlayerStunInvincibleDie.FixedUpdateNetwork()`의 타이머로 관리(입력 게이팅과 무관)

### 중앙 게이팅으로 통합 시 고려사항
1) 변경 내용
   - `SpelunkyPlayerController.FixedUpdateNetwork()`에서 상태가 차단 상태면 하위 모듈의 `ProcessInput()` 호출 자체를 생략
   - 각 모듈의 중복 조건문은 단계적으로 제거 가능(유지보수 용이)
2) 안전성 평가
   - 물리 전환은 픽업/던지기 시점의 함수에서 이미 원자적으로 처리되므로, `ProcessInput()` 미호출로 인한 물리 꼬임 없음
   - `IsThrown` 타이머/해제는 전용 컴포넌트에서 계속 동작
   - 사다리/점프의 커스텀 중력은 차단 중 실행되지 않지만, Thrown/Held 상태에서 기대하는 중력값(1 또는 0)으로 유지됨
3) 버튼 래칭(Pressed) 관련
   - 차단 기간 동안 각 모듈의 `ButtonsPrevious`가 갱신되지 않아, 차단 해제 첫 틱에 상승엣지로 감지될 수 있음
   - 이 특성은 현재도(모듈 내부 조기 반환으로) 동일하므로 동작 변화는 없음
4) 부가 영향
   - `PlayerJump`의 로켓 연료 충전/다운점프 타이머 등 입력과 무관한 보정 로직은 차단 중 정지함(의도된 휴면으로 판단)

### 권장 적용 순서(안전한 단계적 정리)
1) `SpelunkyPlayerController.FixedUpdateNetwork()`에서 차단 상태일 땐 하위 모듈 `ProcessInput()` 호출 스킵
2) 충분한 테스트 후, 각 모듈의 중복 게이팅을 제거(또는 경고 로그만 유지)
3) 버튼 래칭이 문제될 경우, 차단 해제 1프레임 동안 강제 `ButtonsPrevious = input.NetworkButtons` 동기화 훅 도입 검토

### 체크리스트
- Held/Thrown에서 부모/바디타입/중력/트리거 전환이 시점에 정확히 한 번만 호출되는지
- 차단 해제 첫 틱에 의도치 않은 `Pressed` 발생이 게임플레이에 유의미한지
- 사다리 중 → 던지기 전환 시, 중력/속도 보정이 기대대로 유지되는지
