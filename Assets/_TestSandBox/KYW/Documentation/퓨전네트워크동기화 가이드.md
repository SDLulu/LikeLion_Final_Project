# Photon Fusion 네트워크 동기화 가이드

## 📖 개요

이 문서는 Photon Fusion에서 네트워크 동기화와 틱 동기화에 대한 이해와 문제 해결 방법을 다룹니다. 특히 `FixedUpdateNetwork()`와 Unity 이벤트 간의 동기화 문제와 해결 방안을 중점적으로 설명합니다.

## 🎯 핵심 개념

### FixedUpdateNetwork()란?
- Photon Fusion의 핵심 네트워크 동기화 함수
- `FixedUpdate()` 이후에 실행되어 물리 시스템과 동기화
- 네트워크 상태가 안정적일 때 실행됨
- 모든 네트워크 관련 로직은 이 함수 내에서 처리하는 것이 안전

### 틱(Tick) 동기화란?
- Fusion의 네트워크 프레임 단위
- 모든 클라이언트가 동일한 틱에서 동일한 로직 실행
- 네트워크 지연이나 불일치를 방지

## 🚨 문제 상황 분석

### 1. AttackCollisionHandler → PlayerHealth → Die() 경로 (정상 동작)
```
1. 플레이어가 공격받음
   ↓
2. AttackCollisionHandler.OnTriggerEnter2D() 호출
   ↓
3. ApplyDamageAndKnockback() 호출
   ↓
4. interaction.TakeDamage(attackDamage) 호출
   ↓
5. PlayerHealth.TakeDamage() 호출
   ↓
6. PlayerHealth.Death() 호출
   ↓
7. playerDeathHandler.Die() 호출
```

**왜 안전한가?**
- 이 모든 과정이 `FixedUpdateNetwork()` 내에서 실행됨
- `OnTriggerEnter2D()`는 Unity의 물리 시스템에서 호출되는데, 이는 `FixedUpdate()`와 동기화됨
- Fusion에서는 `FixedUpdate()` → `FixedUpdateNetwork()` 순서로 실행됨

### 2. 외부 호출 (디버거/PlayerManager) → Die() 경로 (버그 발생)
```
1. PlayerStateDebugger.TestDeath() → playerDeathHandler.Die() 직접 호출
2. PlayerManager.SoftResetAllPlayers() → playerDeathHandler.Die() 직접 호출
```

**왜 문제가 되는가?**
- `Update()` 또는 다른 이벤트에서 호출됨
- 네트워크 틱과 비동기적으로 실행
- 네트워크 상태가 불안정할 수 있음
- `ReleaseObject` 호출 시점에 네트워크 동기화 문제 발생

## 🛠️ 해결 방법: TickTimer를 사용한 지연 실행

### 구현 원리
외부에서 호출된 함수를 `FixedUpdateNetwork()` 내에서 실행되도록 지연시키는 시스템

### 코드 구현

#### 1. 지연 실행 변수 추가
```csharp
[Networked] private TickTimer delayedDeathTimer { get; set; }
[Networked] private bool hasPendingDeath { get; set; }
[Networked] private TickTimer delayedResurrectTimer { get; set; }
[Networked] private bool hasPendingResurrect { get; set; }
[Networked] private Vector3 pendingResurrectPosition { get; set; }
```

#### 2. Die() 함수 수정
```csharp
public void Die()
{
    // 권한 확인
    if (!HasStateAuthority) return;
    
    // 이미 사망 상태라면 중복 처리 방지
    if (IsDead) return;
    
    // 네트워크 상태 검증
    if (!Object.IsValid || Runner == null || !Runner.IsRunning)
    {
        Debug.LogWarning("네트워크 상태가 안전하지 않음");
        return;
    }
    
    // 지연 실행 설정 (다음 FixedUpdateNetwork에서 실행)
    if (hasPendingDeath)
    {
        Debug.Log("이미 죽음 처리가 대기 중입니다. 중복 호출 무시.");
        return;
    }
    
    hasPendingDeath = true;
    delayedDeathTimer = TickTimer.CreateFromSeconds(Runner, 0.01f); // 0.01초 후 실행
    
    Debug.Log("Die() 호출됨 - FixedUpdateNetwork에서 지연 실행 예약 (0.01초 후)");
}
```

#### 3. FixedUpdateNetwork() 구현
```csharp
public override void FixedUpdateNetwork()
{
    // 지연된 죽음 처리 체크
    if (hasPendingDeath && delayedDeathTimer.Expired(Runner))
    {
        hasPendingDeath = false;
        delayedDeathTimer = TickTimer.None;
        
        Debug.Log("FixedUpdateNetwork에서 지연된 죽음 처리 실행");
        ExecuteDeath(); // 실제 죽음 처리 실행
    }
    
    // 지연된 부활 처리 체크
    if (hasPendingResurrect && delayedResurrectTimer.Expired(Runner))
    {
        hasPendingResurrect = false;
        delayedResurrectTimer = TickTimer.None;
        
        Debug.Log("FixedUpdateNetwork에서 지연된 부활 처리 실행");
        ExecuteResurrect(pendingResurrectPosition); // 실제 부활 처리 실행
    }
}
```

#### 4. 실제 실행 함수 구현
```csharp
private void ExecuteDeath()
{
    // 기존 Die() 함수의 모든 로직을 여기로 이동
    // 네트워크가 안전한 상태에서 실행됨
}

private void ExecuteResurrect(Vector3 respawnPosition)
{
    // 기존 ResurrectAt() 함수의 모든 로직을 여기로 이동
    // 네트워크가 안전한 상태에서 실행됨
}
```

    }
}

## 🔍 RPC와 FixedUpdateNetwork의 관계

### RPC 동작 원리
```
1. 클라이언트에서 RPC 호출
   ↓
2. Fusion 네트워크 시스템이 RPC 요청을 큐에 저장
   ↓
3. 다음 FixedUpdateNetwork에서 RPC 실행
   ↓
4. RPC 내부 로직이 FixedUpdateNetwork와 동기화되어 실행
```

### RPC가 FixedUpdateNetwork와 동기화되는 이유
- **네트워크 큐**: RPC 요청이 네트워크 큐에 저장됨
- **틱 동기화**: 큐에 저장된 RPC가 다음 틱에서 실행됨
- **상태 일관성**: 모든 클라이언트가 동일한 틱에서 동일한 RPC 실행

### RPC 사용 시 장점
1. **자동 동기화**: FixedUpdateNetwork와 자동으로 동기화
2. **권한 분리**: InputAuthority와 StateAuthority 역할 분리
3. **네트워크 최적화**: Fusion이 자동으로 네트워크 최적화
4. **코드 간소화**: 지연 실행 시스템 불필요

### RPC 사용 예시
```csharp
// PlayerStateDebugger에서 안전한 죽음 요청
public void TestDeath()
{
    if (playerDeathHandler != null)
    {
        // 직접 Die() 호출 대신 RPC 사용
        playerDeathHandler.RPC_RequestDie();
    }
}

// PlayerDeathHandler에서 RPC 처리
[Rpc(RpcSources.InputAuthority, RpcTargets.StateAuthority)]
public void RPC_RequestDie()
{
    // 이 함수는 FixedUpdateNetwork와 동기화되어 실행됨
    Die(); // 안전하게 실행
}
```

## 🌟 장점

### 1. 네트워크 동기화
- `FixedUpdateNetwork()` 내에서 실행되어 안전
- 모든 클라이언트가 동일한 틱에서 동일한 로직 실행

### 2. 중복 방지
- 이미 예약된 경우 중복 호출 무시
- 여러 번 호출되어도 한 번만 처리

### 3. 지연 최소화
- 0.01초 지연으로 사용자 경험에 영향 최소
- 네트워크 상태가 안정적일 때까지 대기

### 4. 기존 코드 호환
- `Die()` 함수 호출 방식은 그대로 유지
- 기존 코드 수정 없이 안전성 향상

### 5. RPC 사용 시 추가 장점
- **자동 동기화**: FixedUpdateNetwork와 자동으로 동기화
- **권한 분리**: InputAuthority와 StateAuthority 역할 분리
- **네트워크 최적화**: Fusion이 자동으로 네트워크 최적화
- **코드 간소화**: 지연 실행 시스템 불필요
- **표준 방식**: Photon Fusion의 권장 패턴

## 📝 주의사항

### 1. 지연 시간 설정
- 너무 짧으면 네트워크 상태가 아직 불안정할 수 있음
- 너무 길면 사용자 경험에 영향을 줄 수 있음
- 권장: 0.01초 (10ms)

### 2. 상태 검증
- 실행 전 `Object.IsValid`, `Runner.IsRunning` 등 확인
- 네트워크 상태가 안전하지 않으면 실행 차단

### 3. 중복 호출 방지
- `hasPendingDeath`, `hasPendingResurrect` 플래그로 중복 방지
- 이미 예약된 경우 추가 호출 무시

### 4. RPC 사용 시 주의사항
- **RpcSources 설정**: 적절한 권한 설정 필요
- **RpcTargets 설정**: 대상 클라이언트 명확히 지정
- **네트워크 부하**: 과도한 RPC 호출은 네트워크 부하 증가
- **동기화 순서**: RPC 실행 순서가 중요한 경우 주의 필요

## 🔧 문제 해결 체크리스트

### Die() 함수가 제대로 작동하지 않을 때
1. `HasStateAuthority` 확인
2. `Object.IsValid` 확인
3. `Runner.IsRunning` 확인
4. `hasPendingDeath` 상태 확인
5. `delayedDeathTimer` 만료 확인

### ResurrectAt() 함수가 제대로 작동하지 않을 때
1. `HasStateAuthority` 확인
2. `Object.IsValid` 확인
3. `Runner.IsRunning` 확인
4. `IsDead` 상태 확인
5. `hasPendingResurrect` 상태 확인
6. `delayedResurrectTimer` 만료 확인

### RPC가 제대로 작동하지 않을 때
1. **RpcSources 설정 확인**: `RpcSources.InputAuthority`, `RpcSources.StateAuthority` 등
2. **RpcTargets 설정 확인**: `RpcTargets.All`, `RpcTargets.Others` 등
3. **권한 확인**: RPC를 호출하는 클라이언트가 적절한 권한을 가지고 있는지
4. **네트워크 연결 상태**: RPC 호출 시점에 네트워크가 연결되어 있는지
5. **RPC 함수 시그니처**: `[Rpc]` 어트리뷰트와 함수 시그니처가 올바른지
6. **RPC 큐 상태**: Fusion 네트워크 큐가 정상적으로 작동하는지

### 일반적인 네트워크 동기화 문제
1. **FixedUpdateNetwork 호출**: 해당 함수가 제대로 오버라이드되었는지
2. **Networked 프로퍼티**: `[Networked]` 어트리뷰트가 올바르게 설정되었는지
3. **권한 체크**: `HasStateAuthority`, `HasInputAuthority` 등이 올바르게 사용되었는지
4. **네트워크 상태**: `Object.IsValid`, `Runner.IsRunning` 등이 정상인지
5. **틱 동기화**: 모든 클라이언트가 동일한 틱에서 실행되는지
